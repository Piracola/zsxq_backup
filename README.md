# zsxq-sentinel

知识星球私有备份工具:盯住你加入的星球,新内容出现后第一时间抓回本地;已备份的内容被删除、编辑或评论有变动时,立即通过 Telegram 告警。内置 Telegram 菜单机器人,手机上就能翻备份、看评论、对比改动、扫码续期。

设计目标只有一个:**内容在被删之前,已经在你手里。**

## 它做什么

- **即时备份** — 按人类浏览的节奏轮询(默认 30 秒,带随机抖动),每个新话题立即保存完整数据:正文、全部评论和楼中楼回复、图片、附件、音频,原始 JSON 先落盘再渲染 Markdown。
- **删除监测** — 复查搭在同一趟抓取里:列表里每条已归档话题都当场比对修改时间与评论数,不额外发请求。只有「窗口内本该出现、这轮却没出现」的话题才单独确认一次,接口明确说「话题不存在/已删除」才判定被删,限流、5xx、网络异常和凭证失效都不会误报。判定瞬间推送告警,本地已留完整快照。
- **篡改监测** — 话题被编辑时存一份修订快照,并算出逐行差异一起推给你。
- **评论追踪** — 评论数一变就按时间游标补拉一次评论,跟本地基线比对,告警里直接写明「多了几条、谁说了什么」;评论变少时指出少了谁的哪一条。数字不再是唯一的信息。另有一路**评论抽查**:默认每 30 分钟开一批,一批翻 20 条话题的评论区(先挑最久没核过的,窗口里的迟早都轮到),兜住那个计数看不见的变化——楼中楼被删(平台那个数字常常不跟着减)、一轮之内涨了又跌回原数、以及拉增量时漏在缝里的回复。一批不会一次发完,摊在接下来的几次轮询里,一次一个请求。顺带说明:接口的 `comments_count` 数的是「主评论 + 楼中楼」,所以有人回复楼中楼,这个数字是会动的。
- **每个星球独立节奏** — 抓取间隔、每轮条数、复查周期与窗口、评论上限、夜间静默、要不要下图,都能按星球单独设,Telegram 里点按钮即可。
- **Telegram 机器人** — 见下。
- **凭证自助续期** — 凭证失效告警后,在 Telegram 里点一下,扫码即续,全程不用碰电脑。

## Telegram 菜单机器人

配好机器人 token 后自动随哨兵启动,长轮询工作,不需要公网端口。发 `/menu` 进入。

| 命令 | 功能 |
| --- | --- |
| `/menu` `/start` | 主菜单 |
| `/groups` | 列出账号加入的所有星球(名单没拉到时当场拉一次;拉不到会提示凭证可能失效) |
| `/status` | 盯了几个星球、备份多少条、凭证状态、各星球的节奏 |
| `/login` | 生成微信登录二维码发给你,扫码后新凭证自动生效 |
| 直接发几个字 | 按标题搜本地备份,命中的话题直接点进去 |

主菜单有四个入口:**我的星球**、**最近话题**(所有星球的新备份按时间排)、**最近变动**(这次运行里谁被改了、被删了、多了几条评论)、**哨兵状态**。

### 一条话题能做什么

从任何一个清单点进去,先看到一张卡片:标题、作者、时间、类型、点赞/评论/阅读数、精华置顶标记、本地存了多少条评论、服务器上次显示多少条、有没有被改过或被删。下面四个入口:

| 按钮 | 内容 |
| --- | --- |
| 📄 看全文 | 正文按区块发出来(提问 / 回答 / 正文 / 作业 / 解答),图片单独发,附件列出文件名和大小,结尾带原文地址 |
| 💬 评论 | 全部评论分页看(按这一页放得下几条来分,长评论不会被截断),楼中楼跟着父评论显示;缺的可以一键从星球补齐 |
| ✏️ 改动逐行对比 | 每次改动单独一页,标出改了哪几行(`－` 原文 / `＋` 改后),可以来回切;没有改动时也会说清楚 |
| 🔄 跟服务器核对一次 | 当场问一次这条话题现在什么样:评论数、最后修改时间、是不是已经没了 |

### 星球页里能调什么

- **🗂 备份清单** — 这条星球的全部备份,每页 6 条,新的在上,标出 🚫 已删除 / ✏️ 改过 / 💬 评论数
- **📥 拉最新 10 条** — 直接从服务器拉一页(不等备份),给你一份可点的清单;想按老样子一条条发全文,清单底部有按钮
- **💬 评论提醒** — 四档循环,点一下换下一档:

| 档位 | 推什么 | 新评论进不进存档 |
| --- | --- | --- |
| 都提醒 | 有人评论说谁说了什么;评论变少说少了谁的哪条 | 进 |
| 只看新增 | 只推新评论,评论变少不出声、也不去拉 | 进 |
| 只看减少 | 只在评论变少时出声,新评论悄悄存下 | 进 |
| 全关 | 什么都不推,也不再追已有话题的新评论 | 不进 |

不管哪一档,已经存下来的评论都不会被删掉——服务器上没了的,你手里那份还在。
- **🔔 自动推送** — 开启后该星球每个新话题备份完成就推给你,同时自动加进盯守名单
- **✂ 保留条数** — 不限量 / 50 / 100 / 200 / 500 / 1000 之间循环,超出的连同备份文件、修订快照一起清掉
- **⚙ 抓取设置** — 每行点一下换下一个值,当前值写在按钮上,改完立刻生效并写回 `watch.json`:

| 项 | 可选值 |
| --- | --- |
| 抓取间隔 | 15 秒 / 30 秒 / 45 秒 / 1 分钟 / 2 分钟 / 5 分钟 |
| 每轮条数 | 20 条 / 30 条 |
| 删除复查 | 5 分钟 / 15 分钟 / 1 小时 / 6 小时 / 1 天 / 关闭 |
| 复查范围 | 最近 1 / 3 / 7 / 30 天 |
| 评论上限 | 全部 / 20 条 / 50 条 / 100 条 |
| 评论抽查 | 10 分钟 / 30 分钟 / 1 小时 / 3 小时 / 6 小时 / 关闭 |
| 抽查条数 | 每批 5 / 10 / 20 / 30 条 |
| 夜间静默 | 关闭 / 23–7 点 / 22–8 点 / 0–7 点 |
| 图片附件 | 下载 / 跳过 |

列表里没有合用的值,就点最下面那行「✏️ 手动填数值」:选一项,然后直接发个数字给它,秒、分钟、小时、天都认(发「2分钟」「90秒」这样带单位也算),超范围它会告诉你范围并把机会留着。填到一半改主意发 `/cancel` 就行;发任何别的斜杠命令也会自动取消,不会把你后面的话当成数字吃掉。

### 推送长什么样

- **新话题** — 正文(问答分提问与回答)+ 图片,附带「看评论 / 看全文」两个按钮
- **评论有变动** — 「多了 2 条评论(现在共 7 条)」,下面列出是谁、几点、说了什么(楼中楼注明「回复 谁」),按钮直接跳到那一页。评论变少时列出「服务器上不再出现、本地还留着的」是哪些。抽查发现的变化走同一条消息,标题会写「抽查发现评论有变化」
- **话题被编辑** — 哪一块变了、新增几行、删掉几行,附一两行差异,按钮进逐行对比
- **话题被删除** — 提示本地快照还在,按钮直接打开存档

所有开关状态持久化在配置文件里,重启不丢。

## 部署

需要:任意一台 VPS,Python 3.10+

```bash
git clone https://github.com/Piracola/zsxq_backup /opt/zsxq && cd /opt/zsxq
pip3 install -r requirements.txt          # python-telegram-bot + pycryptodome
cp watch.json.example watch.json
vi watch.json        # 至少填 notify.telegram(bot token 和你的 chat_id); groups 可以先留空
python3 -X utf8 test_tg_bot.py           # 自检: 不联网, 验证机器人逻辑
python3 -X utf8 zsxq_watch.py --once     # 试跑一轮
```

`groups` 留空也能起:服务照常在线,机器人在 `/groups` 里挑一个星球打开自动推送,它就会自己进盯守名单。

常驻(推荐 systemd):

```ini
[Unit]
Description=zsxq sentinel
After=network-online.target

[Service]
WorkingDirectory=/opt/zsxq
ExecStart=/usr/bin/python3 -X utf8 zsxq_watch.py
Restart=always
RestartSec=30

[Install]
WantedBy=multi-user.target
```

## 代码结构

| 文件 | 作用 |
| --- | --- |
| `zsxq_watch.py` | 哨兵主程序与唯一入口:轮询备份、删除/篡改/评论监测、IM 告警 |
| `tg_bot.py` | Telegram 菜单机器人(python-telegram-bot 22.x),随哨兵启动,无需单独运行 |
| `tg_topics.py` | 把备份目录读成机器人要展示的东西:清单、标题、评论增量、改动对比(不依赖 telegram,可单独测) |
| `zsxq_archive.py` | 归档核心库(Client / 渲染 / 下载),被 watch 与 bot 共用 |
| `zsxq_login.py` | 微信扫码登录,可独立运行,也被机器人 /login 调用 |
| `zsxq_token.py` | 已 root 安卓机提取凭证(备用) |
| `zsxq_sync.py` | 工作站 → VPS 的 git 推送中转 |
| `test_tg_bot.py` | 机器人离线自检(不联网),改完机器人跑一下 |
| `verify_archive.py` / `zsxq_unpack.py` | 备份校验 / 解包整理 |
| `requirements.txt` | 依赖清单 |

机器人跑在哨兵进程内的独立线程里,自带 asyncio 事件循环:哨兵是同步世界,通过跨线程投递把新话题/评论变动/改动推给机器人;所有拉取、清理、读备份的阻塞操作都丢到线程池,所以你在手机上点按钮时菜单不会被卡住。

依赖方向: `zsxq_watch` → `tg_bot` → `zsxq_login`;`zsxq_watch` 与 `tg_bot` → `tg_topics` → `zsxq_archive`。无反向依赖,配置与备份状态由 Sentinel 单点持有,机器人线程只读共享实例。

## 配置(watch.json)

| 字段 | 说明 |
| --- | --- |
| `groups` | 要盯的星球 ID 列表 |
| `poll_interval` | 抓新话题的间隔秒数,实际带 ±25% 抖动 |
| `page_size` | 每轮拉多少条(`20` 或 `30`,接口实测上限 30) |
| `check_interval` | 窗口内缺席的话题,同一话题两次确认的最小间隔秒数;`0` = 不做确认 |
| `check_batch` | 每轮最多确认几条,免得一次性扎堆 |
| `recent_days` | 确认范围上限:只确认最近 N 天的话题 |
| `max_comments` | 每个话题最多抓多少条评论,`0` = 全部;也决定评论变动比对能看多远 |
| `sweep_every` | 评论抽查:上一批翻完、且距上次开批满这么多秒,才开下一批(默认 1800),`0` = 不抽查 |
| `sweep_size` | 一批翻几条话题(默认 20),按「最久没核过」先后挑。一批摊在接连几次轮询里,一次一个请求 |
| `keep_media` | 是否下载图片与附件;`false` 只留 raw JSON 里的远程链接 |
| `comment_alert` | 评论提醒档位:`both` 都提醒 / `added` 只报新增 / `removed` 只报减少 / `off` 全关(不再追评论)。旧版的 `notify_comments: true/false` 会自动换成 `both`/`off` |
| `group_opts` | 逐星球覆盖上面这些项,例如 `{"12345678901234": {"poll_interval": 15, "page_size": 30}}` |
| `group_keep` | 逐星球只保留最近 N 条 |
| `auth_cache_ttl` | 凭证自检结果复用秒数(默认 1800),省掉每轮一次 whoami;`0` 为每轮都查 |
| `quiet_hours` | 夜间静默 `[起, 止]` 本地小时(支持跨零点如 `[22,6]`),静默期内不轮询,机器人仍在线 |
| `bot_users` | 允许操作机器人的 Telegram 用户 ID;留空则允许所有私聊 |
| `notify.telegram` | bot token 与 chat_id,兼作机器人与告警通道 |
| `notify.*` | 也可选企业微信 / 钉钉 / Bark / 通用 webhook |

`poll_interval`、`page_size`、`check_interval`、`check_batch`、`recent_days`、`max_comments`、`sweep_every`、`sweep_size`、`keep_media`、`comment_alert`、`quiet_hours`、`notify_new` 这几项都可以按星球单独设,写在 `group_opts` 里即可;没写的项沿用全局值。在 Telegram 里点「星球 → ⚙ 抓取设置」改的就是其中大部分(评论提醒是星球页单独那一行),改完立刻生效并写回 watch.json。

请求量参考(单星球):每轮固定 1 次最新列表,复查用的修改时间与评论数都在这份列表里,不再额外请求。评论变多时补拉一次增量(带时间游标,通常 1 个请求);评论变少要整段拉一遍才知道少了谁,这一步只在「都提醒」「只看减少」两档会做——「只看新增」遇到变少什么都不拉,「全关」则两边都不拉。**评论抽查**是一批一批来的:一批翻 `sweep_size` 条(默认 20 条),摊在接下来 `sweep_size` 次轮询里、一次一个请求,所以突发流量只有一条;上一批翻完、并且距上次开批满 `sweep_every` 秒,才开下一批。所以真正的周期是「`sweep_size` × `poll_interval` 和 `sweep_every` 里大的那个」——抓取间隔调得很稀时,一批本身就要翻很久。代价是每批固定 `sweep_size` 个请求,把 `sweep_size` 调小或 `sweep_every` 调大都能省。话题被编辑时才多一次详情 + 一次评论(全关档连这一次也省了)。确认删除仍然只给「窗口内缺席」的话题发。凭证自检按 `auth_cache_ttl` 缓存,不是每轮都问 whoami。想更省,**第一优先是把 `poll_interval` 调大**(它决定轮次总数),其次是「抽查条数」调小或「评论抽查」调大,最后才是把评论提醒调成「全关」。

`check_archived`、`verify_gap`、`confirm_gap` 是旧版的独立复查配置,现在已并入每轮抓取,留在配置里会被忽略,可以删掉。

## 凭证

登录凭证是跟账号绑定的 access token,支持两种获取/续期方式:

1. **微信扫码(推荐)** — Telegram 里发 `/login`,或在 VPS 上跑 `python3 zsxq_login.py`,二维码发到聊天窗口,微信扫码确认后新凭证自动写入并热生效,服务无需重启。协议逆向自网页版登录流程。
2. **手机提取(备用)** — 已 root 的安卓机可用 `zsxq_token.py` 直接提取。

## 数据结构

```
backup/
├── state.json                  # 话题状态总账(标题、评论数、修改时间、删除标记、复查时间)
├── index.md                    # 可读索引(时间 + 标题 + 评论数 + 🚫/✏️ 标记)
├── raw/<gid>/<tid>.json        # 原始 JSON(含全部评论)——最高优先级数据
├── raw/<gid>/<tid>__rev_N.json # 被编辑话题的修订快照
├── deleted/<gid>/<tid>.json    # 确认被删除的话题:删除前完整快照
└── <星球名>_<gid>/              # Markdown + images/ + files/
```

原始 JSON 是本体,Markdown 只是视图。渲染器有 bug 也不会丢数据,`--render-only` 即可从 raw 重渲染。机器人的清单、评论页、改动对比都直接读这些文件,不额外存一份。

## 命令行

```bash
python3 zsxq_watch.py                     # 常驻运行
python3 zsxq_watch.py --once              # 单轮(配 cron 亦可)
python3 test_tg_bot.py                    # 机器人离线自检(不联网)
python3 zsxq_archive.py --list            # 列出账号所有星球
python3 zsxq_archive.py --group <gid>     # 全量归档指定星球
python3 zsxq_archive.py --render-only     # 不联网,从 raw 重渲染
python3 verify_archive.py <备份目录>       # 校验备份完整性
python3 zsxq_unpack.py <备份目录>          # 解包整理
```

## 频率与账号安全

所有请求都按人类节奏设计:各星球按自己的间隔轮询并带随机抖动、单请求限速、删除判定要有「窗口内缺席 + 接口明确报不存在」两个信号、无 WebSocket 长连接。机器人的「拉最新 10 条」是即点即拉,自动推送和评论监测搭轮询顺风车,不产生额外请求模式。
